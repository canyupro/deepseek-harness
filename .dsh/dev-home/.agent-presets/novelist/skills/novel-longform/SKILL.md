# 长篇小说写作 SOP

原则：记忆全部外置到文件，对话上下文只用于当前写作；动笔前读取范围按模型窗口伸缩——窗口小只读三样（弧条目、当前剧情、点名角色卡），窗口大可按需多读台账与相关章节；写完一章立即回写五件套。

## 1. 立项访谈（即开即用）

目标：即使用户只给一句话（如"写一部都市职场恋爱小说"），也能在两轮内问清必问项、按推荐默认填充其余，产出设定包后直接开工。

细节粒度分三层：

- **必问项**：由用户拍板，不替他决定
- **默认项**：用户不答就用推荐值（在设定包回复里列出，用户可一句话推翻）
- **粒度项**：决定世界观、角色卡、大纲写到多细，由用户选，全部带推荐

### 第一轮：必问（一次 ask_user_question 打包 5–6 题，每题第一个选项为推荐）

1. 题材与类型：按用户一句话推导 3–4 个候选（如 都市职场恋爱 / 都市商战 / 职场+悬疑），推荐排第一
2. 目标读者与基调：网文快节奏爽文（推荐）/ 细腻言情 / 出版向写实 / 纯自娱
3. 篇幅与节奏：短篇 <10 章 / 中篇 10–40 章（推荐）/ 长篇连载 40+ 章；并问更新量（每周 3–5 章推荐）
4. 叙事视角：第三人称限知（推荐）/ 第三人称全知 / 第一人称
5. 文风：网文快节奏、对话多（推荐）/ 文艺细腻 / 写实冷峻 / 轻松幽默
6. 尺度与走向：按题材推导选项（如 甜宠/虐恋/黑暗/无虐），并问是否允许 BE

### 第二轮：粒度（一次 ask_user_question 打包 3–4 题，全部带推荐）

1. 世界观粒度：完整设定集（推荐）/ 一句话背景边写边补 / 极简只写刚需
2. 角色卡粒度：主角+重要配角全卡（推荐）/ 出场一个建一个 / 只建主角卡
3. 大纲粒度：全书粗纲 + 当前卷细纲（推荐）/ 只做卷级细纲 / 全书细纲
4. 自由度：允许即兴发挥但回写记录（推荐）/ 严格照纲执行

### 产出设定包（开写门禁）

按选定粒度产出以下文件，并在回复里列出所有已采用的默认项：

- `memory/worldview.md` 草案
- 核心角色卡 `memory/cards/`（含主角，模板见第 2 节）
- `style-guide.md`（文风、视角、单章字数、更新节奏）
- `outline.md`（按选定粒度）+ `arcs/arc-NN.md`（当前弧）

用户确认（"可以/直接开始/没问题"）后才写第一章。

## 2. 项目骨架与角色卡

- 立项时创建骨架：`outline.md`、`state.md`（"尚未开写"）、`summaries.md`、`arcs/`、`chapters/`、`memory/cards/`、`memory/{worldview,timeline,foreshadowing,characters}.md`、`style-guide.md`
- 世界观写入 `memory/worldview.md`：规则、地理、势力、力量体系，分小节
- 每个角色一张卡 `memory/cards/<id>-<姓名>.md`，id 从 c001 递增；同时在 `memory/characters.md` 登记索引行 `id | 姓名 | 身份 | 状态`
- 角色卡模板：

```
# <姓名>（id：cNNN）

## 基本信息
- 年龄 / 性别 / 身份
- 外貌特征
- 首次出场：第 N 章

## 性格与说话
- 性格核心
- 口头禅 / 说话风格
- 动机 / 恐惧

## 关系
- 对 <角色>：<关系>，<当前状态>

## 人物弧线
- 第 N 章：<变化/揭示>
```

## 3. 分弧大纲

- 小窗口：一次只规划一个弧（3–8 章）；大窗口：可一次规划整卷甚至全书
- `outline.md` 追加：每章一行 `[ ] NNN 标题 — 一句话提要`
- 每个弧建 `arcs/arc-NN.md`：每章条目（本章目标、出场角色卡 id、伏笔编号、关键事件）
- 交用户确认后再动笔

## 4. 逐章写作流水线（每章重复）

1. 读 `arcs/arc-NN.md` 本章条目 + `state.md` + 条目中点名的角色卡；上下文宽裕时可按需补读相关台账
2. 写 `chapters/NNN-标题.md`：正文 2000–4000 字（以 style-guide 为准），纯文本，规范引号标清说话人，无表情、表格、代码块
3. 回写五件套（全部小步追加或局部编辑）：
   a. `summaries.md` 追加 `## 第N章 <标题>` + 100–200 字摘要
   b. `state.md` 更新当前剧情（≤500 字，末尾一句 = 本章结尾衔接）
   c. `outline.md` 该章 `[ ]` 改 `[x]`
   d. `memory/timeline.md` 追加本章时间点与事件
   e. 有变化则更新：伏笔 → `memory/foreshadowing.md`（埋设写新行 `FNNN | 第 N 章埋设 | 内容 | 未回收 | 计划回收章节`，回收把状态改为"已回收（第 M 章）"）；角色 → 对应角色卡的"关系/人物弧线"小节；设定 → `memory/worldview.md`

## 5. 并行起草与审稿（大模型可选项）

- 多章并行：用 workflow 给每个子代理一章的简报条目 + 相关角色卡路径，各写各章，主会话统一回写五件套
- 审稿：用 subagent 派"编辑"子代理，读指定章节 + style-guide，返回问题清单与修改建议
- 并行稿一律先落临时文件，由主会话按大纲顺序定稿后再进 `chapters/`

## 6. 断点恢复（新会话续写）

1. 读 `outline.md` 尾部找最近未完成章节 + 对应 `arcs/arc-NN.md` 条目 + `state.md`
2. 直接写下一章；不重读旧章正文

## 7. 修订

- 用户指出问题 → 定位章节 → 局部修改正文 → 更新受影响的摘要 / state / 台账 / 角色卡
- 结构性大改（删章/合并/重排）→ 同步更新 `outline.md`、`arcs/`、`summaries.md`、`memory/timeline.md`

## 8. 纪律

- 一章一回复；会话变长用 /compact，或开新会话按"断点恢复"继续
- 小窗口下禁止通读全书或整本大纲；大窗口也优先按索引读取
- 不把大纲、角色卡或台账全文贴进对话，需要什么读什么
